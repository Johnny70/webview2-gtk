## Coding standard (mandatory)

🔷 Read this **before** writing Vala or C. Match files already in this tree — do not invent a new house style.

**Vala** (`lib/webview2gtk/`, especially `NetworkSession.vala` / `webview.vala`):

- Tabs, not spaces. **No space before `(`** (`set_proxy_settings(`, not `set_proxy_settings (`).
- Copy the surrounding file’s brace / `this.` / `warning(` style. Do not reformat unrelated methods.
- **No** `@"…"` interpolation — concatenate (`"… " + uri`).
- **No** new public Windows-only types or methods. Same `set_proxy_settings` / `NetworkProxyMode` / `NetworkProxySettings` names.
- **No** `#if WINDOWS` in shared-shaped library Vala for this feature (the local host proxy is Windows-only *inside* the host; the Vala API stays WebKit-shaped).
- **Return early.** If an `if` / `if`/`else` sits at the **end** of a method only to wrap the real work, invert it and `return` (or `return false`) on the guard. Do not leave a trailing `else` whose body is the rest of the method. Same rule in new host C (`if (x == NULL) { return FALSE; }`).

```vala
/* Bad — else is the whole method */
if (host == null) {
	warning("…");
} else {
	this.apply(host);
}

/* Good */
if (host == null) {
	warning("…");
	return;
}
this.apply(host);
```

- Docblocks: [docs/code-documentation.md](../code-documentation.md) — multiline `/** … */`, `@param` / `@return` when behaviour is non-obvious, `''name''` inline, `{{{ … }}}` only as a **block** sample. Do not use `` `backticks` `` as inline code (Valadoc block-quote).
- Proposed snippets in this plan are sketches; land them in the existing class with the same indent and docblock voice as the current `set_proxy_settings` comment.

**C host** (`lib/host/`): K&R-ish as in `win32-ui-webview2-automation.c` / `win32-ui-webview2-com-glue.c` (space before `(`, `TRUE`/`FALSE`, stderr `webview2gtk:` prefix). New proxy sources follow that, not a different C dialect.

**Done when:** `git diff` on Vala looks like a local edit of `NetworkSession.vala`, not a restyle.

## Purpose

- 🔷 Ship a **library-owned** local host HTTP CONNECT proxy **in the one `libwebview2gtk-1.a`** (pacman / setup.exe / staging prefix — same artifact).
- 🔷 **Indicate local host proxy mode via existing `set_proxy_settings(CUSTOM, …)`** before any WebView2 environment exists (no meson flag, no new method). After that, **every** view’s environment is created with `--proxy-server=http://<id>@127.0.0.1:<port>`.
- 🔷 Later calls **flag that session’s view(s)** — CUSTOM chains through the given upstream for the life of the window (or until called again); DEFAULT / NONE = DIRECT through the local host proxy.
- 🔷 If the app **never** calls CUSTOM: keep today’s shared `g_env`, no listen socket (hello / browser / DEFAULT-only consumers unchanged).
- 🔷 If the app calls **CUSTOM** **after** a shared (no local host proxy) environment already exists: **error** — the local host proxy must be enabled before the first attach. Do **not** silently latch 5.0’s process-wide `--proxy-server=<uri>`.
- 🔷 No new public Windows-only proxy API. Same `NetworkProxyMode` / `NetworkProxySettings` / `set_proxy_settings` surface.

---

## Why not a meson `-Dembedded_proxy`?

Typical Windows consumers **do not compile this library as a meson subproject of their app**. They either:

1. **Rebuild this repo from source** into a staging prefix, then `dependency('webview2gtk-1')` via `PKG_CONFIG_PATH` / `-Dwebview2gtk_prefix=…` (the usual remote-build: rsync this tree, `meson setup build --prefix=… && meson compile && meson install`, then link the app), or
2. **Link a prebuilt** pacman / `webview2gtk-setup.exe` package (`SYNC_WEBVIEW2GTK=0`-style).

A library meson option would work for (1) only if every rebuild remembers `-Dembedded_proxy=true`. It does **not** work for (2) without a second package. 🔷 Do not add a flag the consumer build must pass; the local host proxy code always ships; **the API call is the switch**.

---

## Why this matters

- 🔷 5.0 can point Chromium at **one** proxy for the **whole process**, and only at env create. Two live views with different egress (or live switch without tearing down `g_env`) is impossible.
- 🔷 The product pattern is: library local host proxy on `127.0.0.1`, per-view ID in the proxy URI, local forwarder decides DIRECT vs upstream. The consumer drops its own in-process forwarder.
- 🔷 Apps that never touch proxy pay nothing extra (shared env, no thread).

## How `set_proxy_settings` works

🔷 Same WebKit-shaped method. Two phases, one rule: **CUSTOM before any window exists starts the server; after that the call only stores a route on the `NetworkSession` and posts it to the proxy thread when a view is bound.**

```text
  CUSTOM before any WebView is shown
           │
           ▼
  start proxy thread (once)
  every later env: --proxy-server=http://<id>@127.0.0.1:<port>
           │
           ▼
  later set_proxy_settings
           │
           ▼
  store mode+URI on that NetworkSession
           │
           ▼
  WebView bind / live update
           │
           ▼
  message to proxy thread: "set view <id> to DIRECT|upstream"
```

| When | What happens |
|------|----------------|
| Never CUSTOM | Shared env, no thread — 4.0 |
| CUSTOM **before** first shown window | Start listen thread. All later views get their own env pointed at the local host proxy. Dummy `http://127.0.0.1` (optional `:port`) = pass-through; any other host = relay for **this** session. |
| CUSTOM / DEFAULT / NONE **after** the local host proxy is on | Write the session fields. If a WebView is already bound, post `SET_ROUTE` to the thread. If not, post when `bind_download_host` assigns the view id. |
| CUSTOM **after** a normal (shared) env already exists | `warning` — too late. No 5.0 Chromium URI latch. |

Loopback URI is **never** an upstream (would loop into the listen socket).

```vala
/* Before any window — start server, all views pass-through */
session.set_proxy_settings(
	NetworkProxyMode.CUSTOM,
	new NetworkProxySettings("http://127.0.0.1", null)
);

/* After a view exists — register that view only */
web.network_session.set_proxy_settings(
	NetworkProxyMode.CUSTOM,
	new NetworkProxySettings("http://upstream.example:8080", null)
);
```

Deadline is **first map/present** (`try_attach`), not `new WebView()`.

**Linux:** dummy `http://127.0.0.1` is a real WebKit proxy (fail-closed if nothing listens). Per-view CUSTOM with a real host is shared; dummy bootstrap may stay `#if WINDOWS` unless Linux already has a localhost forwarder.

## Local host proxy layout (after bootstrap)

Chromium always talks to the library local host proxy. The thread owns the route table.

```text
  WebView 1  --proxy-server=http://1@127.0.0.1:p  ─┐
  WebView 2  --proxy-server=http://2@127.0.0.1:p  ─┼─►  proxy thread
  WebView 3  --proxy-server=http://3@127.0.0.1:p  ─┘         │
                                                             ▼
                                              routes[3] = DIRECT | upstream
```

Each view: own Environment + `UserDataFolder` (`…/wv_<id>`). Shared `g_env` cannot do per-id `--proxy-server`. Chromium sends `Proxy-Authorization: Basic` of `base64("<id>:")`.

### Proxy thread (routes live here)

🔷 Do **not** let the GTK thread mutate the table the accept/CONNECT path reads. The table lives **on the proxy thread**. GTK only posts a message.

```text
  GTK / NetworkSession                         proxy thread
  set_proxy_settings → store on session
  bind view id 3     → post SET_ROUTE(3, uri) ──►  apply routes[3]
  destroy view 3     → post CLEAR_ROUTE(3)    ──►  drop routes[3]
```

Message shapes (💩 names flexible):

- `SET_ROUTE { id, DIRECT | upstream_utf8 }` — “set webview 3 to this proxy”
- `CLEAR_ROUTE { id }`
- `SHUTDOWN`

Queue + wake the thread (event / extra loopback byte / IOCP). 🚫 Shared `routes[]` with a mutex as the primary design — a lock is only OK around the queue, not around CONNECT.

Unknown id → fail-closed (no accidental DIRECT leak).

| Stored on session | Message to thread |
|-------------------|-------------------|
| CUSTOM + 127.0.0.1 / DEFAULT / NONE | `SET_ROUTE(id, DIRECT)` |
| CUSTOM + other host | `SET_ROUTE(id, that URI)` |

### 6.2 Vala `set_proxy_settings` — latch the local host proxy + per-session route

**Why:** Public surface stays WebKit-shaped; the call is the process switch.

**Replace** the 5.0 body in `lib/webview2gtk/NetworkSession.vala` roughly with:

```vala
public void set_proxy_settings(
	NetworkProxyMode mode,
	NetworkProxySettings? settings
) {
	if (mode == NetworkProxyMode.CUSTOM && !wv2_host_ensure_embedded_proxy()) {
		warning(
			"WebView2Gtk: set_proxy_settings(CUSTOM) requires enabling the library proxy before the first WebView attaches"
		);
		return;
	}
	if (mode != NetworkProxyMode.CUSTOM && !wv2_host_embedded_proxy_active()) {
		/* Local host proxy off: DEFAULT no-op; NONE may still latch 5.0 --no-proxy-server. */
		wv2_host_set_proxy_settings((int) mode, null);
		return;
	}

	this.proxy_mode = mode;
	this.proxy_settings = (mode == NetworkProxyMode.CUSTOM) ? settings : null;

	if (mode != NetworkProxyMode.CUSTOM) {
		wv2_host_set_proxy_route(this.proxy_route_id, (int) mode, null);
		return;
	}
	if (settings == null) {
		warning("WebView2Gtk: set_proxy_settings CUSTOM requires NetworkProxySettings");
		this.proxy_mode = NetworkProxyMode.DEFAULT;
		wv2_host_set_proxy_route(this.proxy_route_id, (int) this.proxy_mode, null);
		return;
	}

	string uri = settings.default_proxy_uri;
	if (settings.http_proxy_uri != null && settings.http_proxy_uri.length > 0) {
		uri = settings.http_proxy_uri;
	}
	wv2_host_set_proxy_route(this.proxy_route_id, (int) mode, uri);
}
```

`wv2_host_ensure_embedded_proxy()`:

- If the local host proxy is already running → `true`.
- If no env yet → start listen, set process latch, `true`.
- If shared `g_env` already exists → `false` (error path above).

**Add**

- `private int proxy_route_id = 0;` — assigned when a host binds (or a process-wide allocator if the session must exist before the host).
- On `bind_download_host`: allocate / reuse `proxy_route_id`, **post** `SET_ROUTE` from the session’s stored mode+uri (so a pre-attach CUSTOM is live before first Navigate).
- On `unbind_download_host`: post `CLEAR_ROUTE`.
- Externs:

```vala
[CCode(cheader_filename = "webview2gtk-host-api.h", cname = "vala_webview2_host_ensure_embedded_proxy")]
extern bool wv2_host_ensure_embedded_proxy();

[CCode(cheader_filename = "webview2gtk-host-api.h", cname = "vala_webview2_host_set_proxy_route")]
extern void wv2_host_set_proxy_route(int route_id, int mode, string? proxy_uri);

[CCode(cheader_filename = "webview2gtk-host-api.h", cname = "vala_webview2_host_clear_proxy_route")]
extern void wv2_host_clear_proxy_route(int route_id);
```

**Remove**

- Process-global `vala_webview2_host_set_proxy_settings` latch used as Chromium URI.
- Late-call “restart required for Chromium proxy flags” warning (5.0).

**Replace** the `set_proxy_settings` docblock: first call before attach enables the local host proxy; further calls are live routes; too-late call errors.

### 6.3 Loopback CONNECT proxy (host)

**Why:** The library is the only proxy Chromium trusts; it demuxes by Basic user-id and chains or connects out.

Behavior:

- Listen `127.0.0.1:0` (ephemeral). Start from `ensure_embedded_proxy` **before** the first local-host-proxy mode `CreateCoreWebView2EnvironmentWithOptions`.
- One accept thread; 💩 blocking worker per connection or a small completion-port pool — keep deps to `ws2_32` only.
- Parse `Proxy-Authorization: Basic` → route id. Missing / unknown id → fail-closed (💩 so a mis-wired view does not leak DIRECT).
- HTTP and HTTPS `CONNECT`:
  - DIRECT: connect to the request target.
  - CUSTOM: HTTP proxy protocol to the upstream (CONNECT for HTTPS; 💩 absolute-form HTTP for cleartext).
- Route table **only written on this thread**. `set_proxy_route` / `clear` enqueue `SET_ROUTE` / `CLEAR_ROUTE` and return; they do not touch `routes[]`.
- Shutdown: post `SHUTDOWN` when the last host is destroyed (or process teardown).

🚫 MITM / CA inject / decrypt. Tunnel only.

🚫 PAC.

### 6.4 Per-host Environment + UserDataFolder (only after local host proxy latch)

**Why:** Chromium will not give two controllers different `--proxy-server` values on one env; unique folders force independent network contexts.

**Where:** `win32-ui-webview2-com-glue.c`, `win32-ui-webview2-loader.c`, `win32-ui-webview2-automation.c`, `win32-ui-webview2-host-priv.h`.

**When local host proxy latch is on:**

- **Add** `int route_id` and `ICoreWebView2Environment *env` on `WebView2Host`.
- Allocate `route_id` at host create (`InterlockedIncrement`).
- **Replace** `g_env` reuse: each `vala_webview2_com_begin_host` creates **that** host’s env (waiter queue becomes per-host, not a shared 8-slot fan-out).
- **Replace** loader `g_create_env_with_options(NULL, NULL, options, handler)` with `(NULL, user_data_folder, options, handler)`.
- **Replace** `vala_webview2_host_create_environment_options` with a per-host builder that **always** appends  
  `--proxy-server=http://<id>@127.0.0.1:<port>`  
  (quotes only if we must; match Chromium’s accepted form). Do **not** append the consumer URI. Do **not** append `--no-proxy-server`.
- Destroy host: Release controller, then that env; leave the profile dir (💩 wiping profiles mid-run is a footgun).

**When local host proxy latch is off:** keep today’s shared `g_env` + `userDataFolder = NULL`. No listen socket.

`vala_webview2_host_environment_created()`: 💩 “any env exists” is still fine for autoplay/webdriver create-time flags. `ensure_embedded_proxy` must distinguish **shared** env vs local-host-proxy mode env.

## Acceptance

1. 🔷 No CUSTOM: shared env, no listen socket (hello unchanged). DEFAULT/NONE do not start the local host proxy.
2. 🔷 `set_proxy_settings(CUSTOM, …)` before first attach: listen on 127.0.0.1; every later view’s args contain `http://<id>@127.0.0.1:<port>`; unique `UserDataFolder` per view.
3. 🔷 CUSTOM on one session routes that view through the given upstream (fail-closed if upstream is dead); other live views stay DIRECT.
4. 🔷 Changing CUSTOM ↔ DEFAULT on a live local-host-proxy mode session retargets **without** env recreate.
5. 🔷 `set_proxy_settings` after a shared env already exists → warning, no Chromium URI latch.
6. 🔷 Destroying a view drops its route row; other views keep working.
7. 🔷 `--smoke-proxy` `TEST_PASS` on the default packaged lib.
8. 🔷 Docs / README match (no meson flag, no “5.0 process-wide latch” as the supported story).

## Open points (in the plan, not blockers to authoring)
